## 💾 1. Storage & Cloud Sync Architecture

The system operates on two distinct data-handling paths. Google Sheets updates and Google Drive folder backups do not sync simultaneously:

### 1.1 Live Google Sheets API Path (Real-Time UI Submissions)
- **Mechanism**: When users interact with the **Product Launch** or **Hub Launch** features (such as appending new hub configurations, expansions, or product replacement mappings), updates are written **directly to the live Google Sheets worksheets** via the Google Sheets API.
- **Drive Behavior**: These live actions **do not** write files or trigger synchronization uploads to the Google Drive folder. The live Google Sheets documents remain the active source of truth.

### 1.2 Remote Storage Sync Path (Google Drive / Supabase Backups)
- **Mechanism**: File-based artifacts (such as calculation outputs, data parquets, and historical actuals) are managed by a cloud sync manager according to the configured `STORAGE_BACKEND` (set to `drive` or `supabase`).
- **Startup Pull**: When the backend container boots, it executes `pull_all_artifacts()` in a background thread to download existing files from the remote storage folder to local server directories.
- **Auto-Pilot Push**: Synchronization uploads to remote storage (`push_all_artifacts()`) are only triggered upon the completion of an **Auto-Pilot baseline run** or via manual execution of the sync script [`backend/scripts/push_pipeline_storage.py`](file:///c:/Users/sumitkumar.nayak/Desktop/forecast-pipeline-v2/backend/scripts/push_pipeline_storage.py). Normal page actions on the portal do not trigger file uploads.
